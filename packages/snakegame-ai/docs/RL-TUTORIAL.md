## 1. 你是怎么学会贪吃蛇的

回想一下你第一次玩贪吃蛇。没人给你讲规则，你按了几个键，蛇动了，然后
你撞墙死了。第二局你离墙远一点就转弯，活得久了一些。玩到第一百局的
时候，你早就不用思考了：食物在左边，脑袋一歪就过去了。

把这个过程拆开，其实只有三样东西：

1. 你看到了什么（蛇的位置、食物的位置）
2. 你做了什么（左转、直行、右转）
3. 你得到了什么（吃到食物很爽，撞墙很烦）

**强化学习就是让程序重复这个过程几百万次。** 你用了一百局学会的东西，
它用一百万局，但它每局只要几毫秒。就这么简单，剩下的全是工程细节。

有一样东西它比你惨：你没有说明书，它连"说明书应该长什么样"都没有。
它对游戏的一切认知，只能从"做动作之后发生了什么"里攒出来。

## 2. 强化学习的基本框架：一个循环

所有强化学习都可以画成同一张图：

```
                 ┌────────────┐
     动作 a      │            │      状态 s
   ┌───────────►│   智能体    │◄───────────┐
   │            │  (Agent)   │            │
   │            │            │      ┌─────┴─────┐
   │            └────────────┘      │           │
   │                                │   环境    │
   │            ┌────────────┐      │(Environment)│
   │   奖励 r    │            │      │           │
   └───────────◄│            │      └───────────┘
   (吃食物 +1,   │  没有,就    │
    撞墙 -1)     │  是环境本身) │
                └────────────┘
```

（智能体左边其实没有实体，奖励是环境顺手发出来的，画出来只是为了看着
清楚。）

对应到贪吃蛇：

| 术语 | 贪吃蛇里是什么 |
|---|---|
| 状态 s (state) | 蛇头周围 15×15 的视野 + 11 个全局数字（见 MODEL.md） |
| 动作 a (action) | 左转 / 直行 / 右转，三选一 |
| 奖励 r (reward) | 吃食物 +1，撞墙/障碍/自己 −1，每步 −0.01 |
| 智能体 | 那个神经网络 |
| 环境 | `SnakeGameEnv`，一局完整的游戏 |
| 一局 (episode) | 从出生到死（或超时）的完整过程 |

循环跑起来就是一条时间线：

```
t=0      t=1      t=2      t=3           t=7
看到 s0──►做 a0──►看到 s1──►做 a1──► ... ──►吃到食物!
          得 r0     得 r1                  得 r7=+1
```

把一局的 (s, a, r) 按顺序记下来，叫一条**轨迹** (trajectory)。

在这里停一下，注意一个和平时写程序很不一样的点：环境有随机性。同样是
"食物在右边"，这局蛇长 3 节，下局长 5 节，地图也换了。所以状态到奖励
之间没有确定的函数关系，只有概率关系。强化学习从头到尾都在跟这种
不确定性打交道。

## 3. 最麻烦的问题：奖励来晚了

看这样一局：

```
t=0        t=1        t=2        t=3        t=4
  ●食物
                       蛇头
 ──►转弯!  ──►直行     ──►直行    ──►直行    吃到 (+1)
 好棋 ✓                                                    
 时刻 t=0 这步转对了，但奖励在 t=4 才到。
```

t=0 那个转弯是好棋，可它拿到的即时奖励是 −0.01（步数惩罚）。如果智能体
只看每一步的即时奖励，它学到的将是"所有动作都差不多糟糕"，永远学不会
提前转弯。

这个问题的学名叫**信用分配问题** (credit assignment)：一个好结果出来
了，功劳该记在前面哪一步头上？

强化学习的解法相当粗暴但有效：**一个动作的好坏，看它之后所有奖励的总
和**。t=0 转弯这一步的"总分"是 −0.01 −0.01 −0.01 −0.01 + 1 = 0.96，
正的，好棋。t=0 直行撞墙的那条时间线，总分是 −0.01 −1 = −1.01，坏棋。

这个"之后所有奖励的总和"有个名字，叫**回报** (return)：

```
回报 G = r(t+1) + r(t+2) + r(t+3) + ...
```

实际用的版本还要给未来的奖励打折，叫**折扣因子** γ (gamma)，本项目取
0.99：

```
G = r₁ + 0.99·r₂ + 0.99²·r₃ + 0.99³·r₄ + ...
```

打折的理由很实际：越远的未来越不确定。这局能不能活到 100 步之后还两说，
先把眼前的奖励当真，远期的打个折。γ=0.99 意味着 100 步后的奖励只值现在
的 37% 左右；γ 取 0 的话智能体会变得极度短视，只吃嘴边的食物。

```
一个 +1 的奖励，随距离衰减的价值：

距离    0步    10步    30步    60步    100步    200步
价值   1.00   0.90    0.74    0.55    0.37     0.13
       ────────────────────────────────► 时间
```

γ 在 `train.py` 里是个超参数。蛇这个游戏节奏快，食物经常就在几十步内，
0.99 是个舒服的取值。

## 4. 局面值多少钱：价值函数

现在换个视角。假设你是个算命先生，蛇走到某个局面，你掐指一算："这个局
面，往后平均能挣 0.8 分。"这个"平均回报"就是这个局面的**价值**。

**状态价值函数 V(s)**：从状态 s 出发，按当前策略一直走下去，能拿到的
期望回报。

```
V(局面) = 这个局面平均能挣多少分

V(食物就在正前方一格)      ≈ +0.95   很值钱
V(蛇头三面是墙)            ≈ -0.90   基本要完
V(开局，食物很远)           ≈ +0.02   不好说
```

顺带一提，"按当前策略走下去"这个前提很重要。同一个局面，菜鸟策略和高手
策略的价值天差地别。V 是策略的函数，策略变好，所有局面的价值都会上涨。

还有个兄弟概念，**动作价值函数 Q(s, a)**：在状态 s 里 specifically 做了
动作 a，之后的期望回报。

```
V(s)  = 在 s 这个局面，平均能挣多少      (不管做什么动作)
Q(s,a) = 在 s 这个局面，做了 a 能挣多少   (指定动作)
```

两者关系：V(s) 就是把所有动作的 Q 按策略的概率加权平均。

这一节在后面的工程里对应**价值网络（critic）**：一个输入状态、输出一个
数字的小网络。它自己不控制蛇，它的作用是给别的网络当裁判。往下看。

## 5. 学会走路：策略和策略梯度

**策略** π(a|s) 就是智能体本身：输入状态，输出每个动作的概率。

```
        蛇头正前方是食物
             │
             ▼
      ┌─────────────┐
      │    策略 π     │────►  左转  3%
      │  (神经网络)   │────►  直行 94%   ◄── 大概率直行，很合理
      └─────────────┘────►  右转  3%
```

刚初始化的网络输出大概是 33% / 33% / 33%，一条随机的醉蛇。训练的目标
就是把这个分布调成"会玩的分布"。

怎么调？直觉出奇地简单，就一句话：

> **如果一个动作之后拿到了高回报，就提高它的概率；拿到了低回报，就降低。**

这句话翻译成梯度，就是强化学习里最重要的一个公式（策略梯度）：

```
∇J = E[ ∇log π(a|s) · G ]
```

拆开看一点都不吓人：

- `∇log π(a|s)`：把"动作 a 的概率"往上调的梯度方向。神经网络课里
  做分类任务时，交叉熵损失求导出来的就是这个东西。
- `G`（回报）：当权重。回报高，这次"往上调"就调得狠；回报是负的，
  方向反过来变成往下调。
- `E[...]`：期望，意思是对很多很多局取平均，因为单局的运气成分太大。

在贪吃蛇里，这个公式的效果是：每局游戏结束后回头看，凡是"之后回报为
正"的转弯，下次遇到类似局面就多转一点这个方向；凡是"之后很快就死"的
动作，下次就少做一点。做上百万次，蛇就学会了。

## 6. 好多少才算好：优势函数

第 5 节的方法有个实际问题：**所有正回报的动作都会被加强，哪怕这个动作
其实很烂。**

举例。你玩一局顺风局，局面本身就好（食物就在附近），随便乱走最后也吃了
3 个食物。用原始回报 G≈+3 去加大每个动作的概率，那些臭棋也被加大了。
下一局局面差，同样的动作全灭，又一起被压制。信号忽左忽右，学得又慢又抖。

问题的根源：回报里混着"局面本身的好坏"和"这步棋的好坏"两种成分。
要分离它们，把局面好坏减掉就行。

回忆第 4 节：V(s) 正是"这个局面平均能挣多少"。拿实际挣到的减去平均
应得的：

```
优势 A = 实际回报的估计 − V(局面)

顺风局乱走:  实际 +3,  平均 +2.5   →  A = +0.5   (还是加了,但只加一点点)
顺风局妙手:  实际 +4,  平均 +2.5   →  A = +1.5   (确实该加)
逆风局苟活:  实际 -0.5, 平均 -1.5  →  A = +1.0   (输了也是好棋!)
```

第三行是这个思想最漂亮的地方：局面很差时少输就是赢，用原始回报看是负的
该被压制，用优势看是正的该被加强。

策略梯度公式升级成：

```
∇J = E[ ∇log π(a|s) · A ]
```

形状没变，只是把 G 换成了 A。方差小了一大截，训练稳了很多。

工程上 A 不直接算，用一个叫 GAE（广义优势估计）的方法从每步的奖励和 V
的差值里拼出来。原理就是上面这个减法，细节可以以后再抠。

## 7. PPO：小步快跑的策略梯度

到第 6 节为止的算法已经能用了（这就是最早的 REINFORCE 系算法），但有
个隐患：**一步更新走多大，没人管。**

想象你在山里找山谷，每一步只根据脚下的坡度决定方向和步长。坡度陡的时候
你会迈一大步，然后一脚跨过山谷直接上了对面的山坡，比原来还高。神经网络
更新也是一样：某一批数据特别"好"（比如全吃了食物），梯度会猛推策略，
一下推过头，策略崩了；崩了的策略采出来的数据更烂，恶性循环。

PPO (Proximal Policy Optimization, 近端策略优化) 的解决方案克制得可爱：
**允许你更新，但新旧策略不能差太多，超了就掐掉。**

具体做法。设同一个状态下，新旧策略对动作 a 的概率比值：

```
r = π新(a|s) / π旧(a|s)
```

- r > 1：新策略比旧的更喜欢这个动作
- r < 1：新策略比旧的更不喜欢

PPO 的目标函数（要最大化的东西）：

```
目标 = min( r·A,  clip(r, 1-ε, 1+ε)·A )      ε 通常取 0.2
```

clip 的意思是把 r 强行限制在 [0.8, 1.2] 区间内。画出来：

```
目标函数值
  │                      ╱ 1.2·A
  │                    ╱
  │  A>0 时          ╱   ← 斜坡在 r=1.2 处被削平:
  │                ╱        再怎么喜欢这个动作,
  │              ╱          加成封顶 20%
  │────────────╱──────────────────► r
  0.8         1            1.2

  │─────────────╲  ← A<0 时同理,在 r=0.8 处削平:
  │               ╲     再怎么想远离这个动作,
  │                ╲    幅度也封顶
  │                 ╲ 0.8·A
```

翻译成人话：

- 一个动作优势为正，PPO 鼓励加大它的概率，**但最多加大 20%**。
- 优势为负，鼓励减小，同样封顶。
- 想一步登天？clip 把你的梯度直接削成 0，免谈。

这就是"近端"(Proximal) 的含义：只在旧策略的邻近区域里信任这次更新。
每轮更新完，新策略变成下一轮的"旧策略"，如此小步迭代。

PPO 还有一副骨架叫 **actor-critic**（演员-评委），两个网络分工：

```
             状态 s (视野 + 标量)
            ┌─────┴─────┐
            ▼           ▼
        ┌───────┐   ┌───────┐
        │ actor │   │ critic│
        │ 策略π │   │ 价值V │
        └───┬───┘   └───┬───┘
            ▼           ▼
        动作概率      局面打分
        (下场玩游戏)  (算优势 A 给 actor 当学习信号)
```

actor 负责"玩"，critic 负责"评价玩得好不好"。critic 自己用普通的回归
训练：预测每个局面的价值，拿实际回报当目标，误差平方最小化。actor 用
第 6 节的优势梯度更新。两个网络共享同一套特征提取（就是 MODEL.md 里
那张 CNN 结构图的双头部分）。

为什么这套东西流行了这么多年？效果好、代码短、超参不娇气。一个 clip
就能稳定训练，性价比极高。本项目用的 stable-baselines3 的 `PPO` 类，
核心逻辑全在上面这几段里。

## 8. 串起来：这个仓库的训练全流程

现在把前面所有概念装进 `train.py` 的主循环。一次训练迭代长这样：

```
┌────────────────────────────────────────────────────────────┐
│ 第 1 步：采样（64 条蛇同时玩，各 256 步）                      │
│                                                            │
│   64 个 SnakeGameEnv（藏在 Python 进程内的 V8 引擎里）        │
│        │ 每步: actor 给出 64 个动作                          │
│        ▼                                                   │
│   收集 64 × 256 = 16384 条 (s, a, r) 记录                   │
└────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌────────────────────────────────────────────────────────────┐
│ 第 2 步：算账（不玩游戏，纯计算）                              │
│                                                            │
│   critic 给每个 s 打分 → 结合实际奖励算每步的优势 A           │
│   (GAE: 第 6 节的减法, 加了些平滑技巧)                        │
└────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌────────────────────────────────────────────────────────────┐
│ 第 3 步：更新（梯度下降, 一般重复 10 个 epoch）                │
│                                                            │
│   actor:  往 ∇log π·A 的方向更新, clip 封顶 ±20%   (第 7 节) │
│   critic: 回归拟合各局面的回报                     (第 4 节) │
└────────────────────────────────────────────────────────────┘
                          │
                          ▼
              回到第 1 步, 用更新后的策略继续采样
              (旧数据全部丢弃, 下一轮只信新策略采的数据)
```

三个步骤对应的概念：

| 步骤 | 用到的东西 | 在哪节讲的 |
|---|---|---|
| 采样 | 策略 π、轨迹、奖励 | 2, 5 |
| 算账 | 价值 V、优势 A、γ 折扣 | 3, 4, 6 |
| 更新 | 策略梯度、clip、actor-critic | 5, 7 |

训练中值得盯的曲线（`uv run --package snakegame-ai tensorboard
--logdir .../output/tensorboard`）：

- `rollout/ep_score_mean`：平均每局得分（吃到几颗食物）。**核心指标**，
  最直观的"蛇有多强"。这条线涨，说明蛇在变强。
- `rollout/ep_rew_mean`：平均每局总奖励（含 step/death 等惩罚项和塑形
  项），走势应与 ep_score_mean 大体一致。附带 `ep_len_mean` 是平均
  局长：先变长（学会活命）再适度变短（学会高效行动）。
- `train/explained_variance`：critic 的预测准不准。1.0 是满分，0 附近
  等于瞎猜。健康训练中它应该爬到 0.8 以上。
- `train/approx_kl`：每轮更新新旧策略的实际差距。常年远大于 0.02 的话，
  说明在用大步幅硬闯——本项目已设 `target_kl=0.03` 让它自动刹车，
  若仍冲高可调小学习率。
- `train/entropy_loss`：策略的探索余量（Discrete(3) 满探索约 −1.1）。
  早期掉到 −0.3 以下（近确定性）而 ep_score_mean 还趴着，说明探索
  死得太早——这正是加 `ent_coef=0.01` 熵奖励的原因。
- BC+PPO 路线（`imitate.py`）另有 `bc/cross_entropy`、`bc/value_mse`：
  行为克隆阶段的 actor 与 value head 起点水平。

对了，还记得第 1 节说"你用一百局学会，它用一百万局"吗？64 条蛇并行、
每秒上千步，一百万步其实只要十几分钟。所谓的"大量试错"，在机器的时间
尺度上很便宜。

## 9. 常见困惑

**Q: 蛇会不会"推理"出我的意图，设陷阱围堵食物？**

不会，差得远。它每步只看当前画面，按概率吐一个动作，上一秒发生了什么
完全不知道。它看起来像"有想法"，只是因为训练分布里活得久的蛇恰好都
做了类似的动作。它是一个条件反射机器。

**Q: 为什么不把高手的对局录下来给它抄？**

那是另一条路线（模仿学习），效果好但要先有一个高手。强化学习的卖点恰恰
是只有规则和奖励，老师都不用请。另外 PPO 是 on-policy 算法：每轮更新
只认当前策略采出来的数据，更新完就扔。你录的旧对局对它来说很快就是
"过时的想法"，参考价值一直在贬值。

**Q: 训练曲线时而上涨时而跳水，正常吗？**

正常。环境有随机性，策略本身也在动，单看某几局毫无意义，看滑动平均。
真崩了（奖励跌回随机水平且不回来）一般是学习率太大，clip 都拦不住的
那种大。

**Q: 为什么选 PPO？深度学习不是有更时髦的算法吗？**

对这个问题，PPO 就是那个" boring but works"的答案。离散小动作空间、
每步信息基本可见、仿真极快——贪吃蛇集齐了 PPO 的全部舒适区条件。
先把 PPO 练明白，再碰别的算法也不迟。
